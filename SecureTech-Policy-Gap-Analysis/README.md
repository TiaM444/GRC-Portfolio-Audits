Policy Review & Compliance Gap Analysis: SecureTech


📌 Project Overview

This project involved a comprehensive Gap Analysis of the existing policy framework at SecureTech. I performed an executive-level review of the Compliance Monitoring and Information Security Policies to identify misalignments with industry-standard regulatory frameworks.


🛡️ Regulatory Scope
The analysis evaluated SecureTech’s adherence to major regulatory and security frameworks:

PCI DSS (Payment Card Industry Data Security Standard) 

HIPAA (Health Insurance Portability and Accountability Act) 

GDPR (General Data Protection Regulation) 

ISO 27001 (Information Security Management Systems) 

🔍 Key Findings & Risk Identification
The audit uncovered several critical gaps that posed both technical and compliance risks:


Delayed Incident Reporting: Identified that the 48-hour reporting window was excessive for high-risk environments like HIPAA and PCI, potentially hindering containment.

Access Control Deficiencies: Noted a lack of explicit mandates for the Principle of Least Privilege (PoLP), a core requirement for ISO 27001 and PCI DSS.

Audit Cadence: Determined that quarterly Risk Register updates were insufficient for the high-velocity nature of financial and healthcare data.

Documentation Integrity: Discovered typographical errors and broken guidelines that suggested a lack of formal version control, which could lead to failed external audits.


💡 Strategic Recommendations
I proposed several actionable improvements to mature the organization's security posture:

Accelerated Reporting: Recommended reducing the incident report window from 48 hours to 24 hours to ensure forensic integrity.

Increased Audit Frequency: Suggested moving from quarterly to monthly Risk Register reviews.

Technical Control Implementation: Recommended explicitly defining PoLP alongside Role-Based Access Control (RBAC).

Enhanced Backup Integrity: Proposed augmenting daily backups with automated integrity checks to prevent "silent failures".
